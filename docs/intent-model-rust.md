# Rust-local completed-utterance intent model: research note

**Decision (2026-09-23):** ModernBERT is a viable Rust inference *architecture*, not yet the best proven checkpoint for eaRS. Start any offline comparison with a small ModernBERT-architecture encoder (`jhu-clsp/ettin-encoder-68m`) against `answerdotai/ModernBERT-base` and the existing deterministic router. Neither checkpoint is a trained eaRS intent classifier. Keep all learned decisions shadow-only: the exact-match registry and static policy alone authorize actions; streaming dictation/preview is unchanged.

## What is supported in Rust

- `candle-transformers` **0.9.2**, already present in this machine's Cargo cache, implements `modernbert::ModernBertForSequenceClassification::load/forward`, including a classification head and CLS/mean pooling. eaRS already depends on `candle-core` and `candle-nn` 0.9; adding `candle-transformers` and `tokenizers` would provide an in-process Rust path for a **fine-tuned** safetensors checkpoint and its `tokenizer.json`. The implementation currently returns softmax probabilities, not raw logits: validate output parity and calibration before interpreting scores. Rust support does not establish acceptable CPU/Metal performance or compatibility with an arbitrary exported fine-tune; test those explicitly.
- An alternative is a separately exported **fine-tuned sequence-classification ONNX** model loaded via `ort` plus Rust `tokenizers`. eaRS already pins optional `ort` rc.12 for other engines, with feature/linking/runtime-dylib constraints; reusing it requires an integration spike. The locally cached `answerdotai/ModernBERT-base/onnx/model.onnx` is for the pretrained **masked-language-model** checkpoint, not an eaRS intent classifier. Do not mistake its existence for a ready-to-run classification model.
- Training can occur offline with `uv`/Transformers; only inference must be in Rust. Export model weights, tokenizer, class-label mapping, preprocessing spec, and pinned versions as a reproducible artifact. Keep training transcripts and raw audio private/out of git.

## Which foundation?

| Candidate | Fit and caveat |
| --- | --- |
| Exact registry + mode (no model) | Production baseline: fast, transparent, already available. Cannot recognize unregistered paraphrases; this is intentional for authorization. |
| Ettin encoder 68M | **First learned candidate** for short utterances and shared-device load: ~68M parameters, MIT, `model_type: modernbert` in its published config, so it shares the ModernBERT Rust architecture path. Smaller does not mean more accurate; no eaRS intent results exist. Its current Hub snapshot contains only a PyTorch `.bin` (no published safetensors file); convert offline with a trusted loader for Candle. |
| Ettin encoder 17M / 32M | **Truly small candidates:** MIT, both publish `model_type: modernbert`, so they are candidates for the same Candle ModernBERT architecture after offline safetensors conversion and parity checks; loading has not been tested here. The Hub checkpoints currently publish PyTorch `.bin`, not safetensors. Whether 17M has enough capacity for ambiguous speech is unknown. |
| MiniLM-L12-H384 33M | **Different architecture to compare:** MIT, `model_type: bert`, distilled for short-language understanding. Its card says fine-tune before classification. It would use a different Rust BERT/ONNX loading path and its current Hub checkpoint is a `.bin`. |
| ModernBERT-base | **Quality challenger:** 149M parameters, Apache-2.0, 22 layers, same Rust path; pretrained for masked LM, so fine-tune a classifier. Its 8,192-token context is mostly unused on brief voice commands. Paper/model-card NLU wins do not establish accuracy on quoted commands, near matches, or ASR errors. |
| ModernBERT-large / DeBERTa-v3-base / Kev | Defer unless smaller baselines fail. Large is 395M; DeBERTa-v3-base has 86M *backbone* plus 98M embedding parameters (not an 86M total model). Kev's measured 0.5B synthetic results are prompt-sensitive and produced false command candidates; see [`kev-shadow.md`](kev-shadow.md). General-purpose leaderboard ranks do not decide this task. |

Ettin's paper reports general GLUE averages of **79.2 (17M), 83.5 (32M), 87.2 (68M)**, versus **84.6 for MiniLM-L12 33M** and **88.4 for ModernBERT-base 149M**. Those scores are not evidence about voice command-intent false positives, and smaller models may trade away the precision this task needs. A [paired synthetic comparison](intent-synthetic-eval.md#larger-frozen-synthetic-challenge-and-tiny-encoders) of Ettin 32M, Ettin 68M, MiniLM 33M, and the existing 149M checkpoint on one frozen 1,100-example set found **no model safe to authorize commands**; MiniLM's stronger synthetic command recall came with 124 false candidates among 880 noncommands. Real consented speech is still required. The attraction of Ettin is a lower-cost comparison with the *same* Rust model family. A [synthetic-only ModernBERT-base intent fine-tune](intent-synthetic-eval.md) has since been trained and evaluated under Python/PEFT on Apple MPS. It produced six false command candidates on 40 noncommands in the synthetic test split; it has **not** been run in Rust, evaluated on real voice, or integrated into eaRS.

## Optional separate inference module with adapter hot swapping

A local process is feasible and keeps ML dependencies out of eaRS. [`sys1`](https://github.com/alvarobartt/sys1) (reviewed at `26f7727`, v0.0.2) is now a concrete Rust/Candle decision-server example with token-based batching and CPU/Metal/CUDA. However, its [architecture loader](https://github.com/alvarobartt/sys1/blob/26f7727/src/models/mod.rs) recognizes **Laya only**, not our exported ModernBERT LoRA/classifier checkpoints; neither shared-backbone multi-adapter serving nor numeric parity is solved by installing it. A [zero-shot Laya trial](intent-synthetic-eval.md#rust-sys1--laya-zero-shot-shadow-trial) on the frozen 1,100-case set ran locally on Metal: ~44 ms endpoint p50 but **718/880 noncommands marked command intent**. Use the API and batching as implementation references, not stock Laya as an eaRS command trigger. A small interface can accept a **completed, dictionary-normalized** utterance plus explicit mode and adapter ID, and return a shadow label/abstention, score, adapter/base revisions, and timing. eaRS must never wait on it to display or type ordinary dictation, and its response cannot authorize execution. Use a local Unix socket or loopback with access control; do not send private utterances to a hosted endpoint.

A [CLM-8B reference trial](intent-synthetic-eval.md#clm-8b-zero-shot-shadow-trial) adds a distinct **candidate-ranking** architecture: a frozen Qwen3-8B pooling encoder plus small state/action projection heads and reusable action embeddings. Its Python/vLLM reference server is **not** a tiny Rust encoder. On the same synthetic eaRS challenge it produced **331/880 false candidates** and never chose `uncertain`; it is relevant to larger, stable action sets in agent sessions, not a stock eaRS classifier. A Rust typed-decision frontend could delegate embeddings to an isolated local pooling worker, but must not pretend a fixed-label ModernBERT classifier can rank arbitrary actions. CLM head training needs state–action pairs with reviewed outcomes and compatible pinned encoder embeddings; it is not the same procedure as PEFT LoRA training.

A [local Python/Transformers + PEFT proof](../experiments/modernbert-hotswap/README.md) switches ModernBERT LoRA classifiers with `set_adapter()` and replaces one live by loading a new named adapter before deleting the old one; it does **not** meet a strict Rust-inference requirement. PEFT 0.21's *in-place* `hotswap_adapter()` was tried and fails with `KeyError: 'base_model.model.classifier.bias'` when the task-specific ModernBERT classification head is saved with the adapter. Do not conflate preloaded selection, live replacement, and allocation-free in-place swapping. A Rust process is possible with Candle, but Candle's ModernBERT classifier currently has ordinary linear layers, **not** an out-of-the-box switchable ModernBERT LoRA implementation. Adding LoRA deltas to the actual targeted layers, decoding PEFT adapter weights, and keeping the classifier head + normalization head with each adapter require an implementation and numerical parity tests. ONNX Runtime advertises MultiLoRA with a generic `Run` path, but its published bindings are Python/C/C++/C#/Java, not a verified Rust ModernBERT-classification integration. vLLM documents dynamic LoRA loading and sequence-classification adapters, but its classifier-adapter support requires a single saved linear head and is not proof that ModernBERT's dense/norm + classifier head or local Apple execution work unchanged. None of the Rust, ONNX Runtime, or vLLM adapter paths has been tested here.

Two different operations need distinct handling: **select** an already-loaded adapter by request ID, or **publish** new weights for an existing adapter ID. For publication, stage a versioned artifact in a private allowlisted directory, verify the base/checkpoint and tokenizer hashes, LoRA targets/rank, full head, labels and calibration metadata, run a parity smoke test, then atomically route new requests to the new immutable version. In-flight requests finish on the old version. Never mutate weights in place during concurrent inference unless the runtime explicitly guarantees request-level isolation. Adapter selection is not retraining; new adapters need consented labelled data. LoRA at encoder layers changes the entire forward pass, not just the final classifier head; do not assume one base forward can be shared unchanged across arbitrary adapters. With one small classifier, one fixed full fine-tune (or a few independently loaded models) may be simpler than dynamic LoRA.

Sources: [PEFT adapter loading and hot swapping](https://huggingface.co/docs/transformers/en/peft), [PEFT classification-head persistence](https://huggingface.co/docs/peft/en/developer_guides/troubleshooting), [ONNX Runtime MultiLoRA bindings](https://onnxruntime.ai/blogs/multilora), [vLLM LoRA limitations](https://docs.vllm.ai/en/latest/features/lora/), and [semantic-router's Rust binding README](https://github.com/vllm-project/semantic-router/blob/main/candle-binding/README.md) (backbone/head sharing is documented there, not a ModernBERT LoRA hot-swap guarantee).

## Go/no-go experiment (offline only)

1. Obtain consented completed utterances, privately stored. Freeze a held-out split by speaker/session and, where possible, by command phrasing; prevent paraphrases and recordings from leaking across train/test. Label literal dictation, exact registered commands in each mode, quoted commands, near commands, self-corrections, ASR errors/noise, and uncertain cases. Preserve the deterministic router's output separately from an annotator's intended semantics.
2. Fine-tune the 68M and 149M checkpoints on the *same* training data, with the same labels and evaluation protocol. Preprocess with the production dictionary **before** inference. Use uncertainty/abstention thresholds chosen on a validation split, not on the held-out test set. A softmax maximum is not itself calibrated confidence.
3. Compare deterministic routing, both fine-tunes (and Kev only if desired) on identical held-out cases. Report confusion by class/mode, false command candidates per non-command utterance, missed candidates, calibration/coverage at each abstention threshold, and slice results for quotes, near matches, and ASR errors. Report counts and intervals, not just accuracy.
4. For each candidate, verify tokenization and scores against the training framework on fixed inputs. Benchmark warm and cold p50/p95/p99 completed-utterance inference in Rust on CPU and Apple Metal where supported, both alone and with eaRS + PhoneLLM busy. Measure model load/memory separately. No model call in the per-word preview or command executor.
5. Prefer the smallest model that meets measured error, resource, and latency budgets for the *shadow* use case. If it adds no useful information beyond exact matching, use **no model**. Never promote candidate output to command authorization.
